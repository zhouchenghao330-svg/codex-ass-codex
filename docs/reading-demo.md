# /adhd 阅读交互 Demo

独立 Rust 终端实验，复用正式界面的 Markdown、宽字符绘制、表格复制和选区渲染。不调用 Codex，不启动 Python 会话服务，不读写 `.codex-room`，可以与正在运行的 Room 并存。正式 Room 已通过 `/adhd` 接入方案 5：仅窄栏居中，保留原有配色；`/adhd on`、`/adhd off` 明确开启或关闭，按房间保存。其余聚焦效果仍仅供实验。

```sh
uv run python scripts/reading_lab.py
```

开发实验首次需要 Rust，本机已构建好；正式 `codexroom` 的下载启动方式保持不变。

| 键 | 对比方案 |
| --- | --- |
| 0 | 原样显示：比较基线 |
| 1 | 行阅读尺：当前行与相邻行 |
| 2 | 段落聚焦：突出整个自然段、列表项或表格逻辑行 |
| 3 | 段落＋行：加当前行提示；超过八行的长段只突出附近五行 |
| 4 | 窄栏＋聚焦：与 3 相同，正文最多 92 列并居中 |
| 5 | 仅窄栏居中：同样的宽度，保留原有配色，不加聚焦、压暗或行提示 |

默认方案 3。所有方案使用同一份模拟讨论，包含多成员、中文长段、列表、代码、表格、diff 和长链接。切换 0–3 不改变排版；4、5 使用相同的窄栏布局，尽量保持同一阅读段落。可用 `uv run python scripts/reading_lab.py --mode 5` 直接打开纯居中方案。

- 移动鼠标：改变阅读焦点；离开正文恢复普通亮度。空白分隔行不会抢走焦点。
- `D`：切换“轻微压暗其他文字”和“其他文字不变，只给当前范围加浅底色”；`+`/`-` 调节压暗强度。
- 空格或点击正文左侧 `›`：锁定焦点，显示 `◆`；Esc 解锁。正文单击和拖选仍用于文本选择。
- `J`/`K`：下一段/上一段，并锁定；代码和表格按较细的阅读单位移动。
- 滚轮、方向键、PageUp/PageDown：滚动。Home/End：开头/末尾。锁定时滚动不会改变文档中的焦点。
- 拖选正文后 `⌘C` / Ctrl+C 复制，Esc 取消选区。保留选区时暂停悬浮和历史重排；可以先打开 F2 再拖选测试。调整宽度会清除选区。
- `F2`：开始/暂停模拟流式输出。只向末尾追加，不自动追底；不产生模型调用。
- `Q` 或 Ctrl+Q：退出并恢复终端。Ctrl+C 无选区时退出，⌘C 无选区时仅提醒。

这里的段落/列表信息来自预先分好的结构化样例，用于比较交互和视觉效果；生产版需从真实 Markdown 解析结果保存语义边界。Demo 的拖选不包含正式版全部增强操作，例如拖到边缘自动滚动、双击选词和转发。

重点比较：长段落里是否容易丢位置、移开鼠标后能否接着读、切换明暗是否刺眼，以及流式输出时拖选是否仍然跟手。终端自动检查只能验证状态与字符结果，主观舒适度由实际体验决定。
