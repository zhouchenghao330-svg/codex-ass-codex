已提交的版本已有独立 Codex 成员、中文名字与改名、工作目录、颜色、Markdown、工具详情与文件 diff、追加消息、全部／单人视图、输入补全、长粘贴与图片块、消息折叠、选区转发、多人点名和返回来源。

最近已提交的两项是 `/focus all` 和“返回来源回到最新消息”。这些不是待实现功能。

当前未提交的功能是：**将 A 创建的原生子代理 B 显示为成员，用户能看完整原话，并与同一个 B 连续讨论，再带回 A。** 当前代码是开发草稿，不能当作完成版发布。

## 用户实际使用方式

1. 用户与 A 讨论问题、实现和想法。
2. 用户要求 A 整理材料，并创建／联系 B，先讨论而非直接实施。
3. 用户亲自读 B 的意见，与 B 往返几轮，直到满意。
4. 用户将选中的内容连同自己的判断交回 A，继续讨论和实施。
5. 需要审查时，回到同一个 B，而不是每次新建一个审查会话。

第一版入口用自然语言，例如：

```text
@A 整理当前实现和我的想法，创建一个叫 B 的原生子代理，请他先提意见。
我会过去跟他聊，先别实施，也不要关闭 B。
@B 从你的角度看，这个方案还有什么问题？
```

成员不预设身份、职责或默认数量；名字由用户决定。后台完成只作轻量提醒，不强制切走用户视图。不会因群里出现消息就唤醒全部成员，也不自动启动无限讨论。

## 已验证的协议事实

以本机 `codex-cli 0.163.0` 为依据：

- 原生子代理与 Room 独立 root 不是一回事；保留原 child thread，不能新建 root 冒充续聊。
- 当前 MultiAgent V2 子代理可能返回 `canAcceptDirectInput=false`，禁止直接 `turn/start` 和 `turn/steer`。
- 真实协议探针已验证：创建 B、读取完整回复、通过父代理 `followup_task` 联系同一个 B，再获得下一轮回复。
- 子代理附加通过 `thread/resume`；恢复时先恢复所属 root，不给 child 强塞 root 的配置覆盖。
- 完整工具记录要使用分页 turns/items API，不能依赖只含最终答案的摘要。
- 子代理的中间输入可能不在历史 userMessage 中公开，不能依赖在 child 历史里查找自定义标记来确认投递。
- 本地源码显示 `turn/interrupt` 没有 start/steer 的相同直接输入限制；**直接中断仍需实际验证**。草稿目前仍使用父代理转交停止指令，不应据此声称停止已做完。

## 恢复开发时还要完成

### 消息与原生会话

- 父子会话发现与恢复去重，处理启动恢复和实时事件同时发生的竞争。
- 尽早订阅子代理请求，避免刚创建时的审批／补充问题被当作无人处理而拒绝。
- 确认分页历史与实时输出合流不重复、不把已完成 turn 降回运行中。
- 转交消息的确认、失败、父代理停止、连接断开、删除与取消统一收尾；不对状态不明的消息盲目重发。
- 处理父代理忙时 steer 的确认竞争；隐藏内部转交请求，但保留可理解的投递状态和真实回复。
- 子代理的工具失败、文件编辑、时间和运行状态与普通成员一致。

### 停止、删除和设置

- 实测直接 `turn/interrupt`；只有确认停止后才能显示空闲或完成删除。
- 停止子代理还要处理尚未发出的转交请求，防止停止后又被旧请求唤醒。
- 删除成员清理订阅、记录索引与待转交内容；递归关系和失败恢复明确。
- 子代理模型、权限受原生父子机制约束，界面不能显示一个实际上未生效的独立配置。
- 旧 child 暂时无法恢复不应让整个 Room 离线；隔离提示错误。

### 验证与交付

- 扩展假 app-server 协议测试：原生创建、多轮续聊、断线恢复、重复事件、停止／删除、其他 root 隔离。
- 实际 Room 端到端验证，而非只有底层 transport 探针。
- 检查已有转发、多点名、输入、历史等回归。
- 根据最终呈现方式补充使用说明，明确 V2 通过父代理转交的现实限制。

## 暂不做

- 自动全员旁听、任意主动插话、无限循环讨论。
- 预设角色／职责或启动时自动创建成员。
- `/add B --parent A` 只是曾讨论的可选快捷方式，尚未承诺为这版必做。
- 已决定保留全屏侧栏、正文点击折叠与应用内选区，使用 Rust 实现；后续子代理功能应接到新服务与界面，不继续堆 Textual。
