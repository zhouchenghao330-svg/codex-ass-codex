## 使用方式

优先体验独立成员协作：创建「开发」「审查」后，让开发「用 Room 公开消息工具把当前实现与目标发给审查，请他提意见」。双方消息在聊天室直接展示，不依赖原生子代理，也不需要复制粘贴。新会话动态工具、旧会话临时 MCP 兼容、停止和防循环边界见 [公开通信说明](public-messages.md)。

协作边界：每次输入刷新名字和忙闲状态，不设固定职责；Room 允许 Full Access 成员主动请求相关帮助。同伴请求不转授用户修改权限，需先向用户说明计划并等批准。此项是模型行为约定，未切换实际沙箱。`expect_reply=true` 要求必要处理后回实质内容，没有立即确认或期限语义；`false` 自动回信仍由路由硬拦截。输入来源与 Codex turn 分开记录，新用户协作不沿用旧链的停止状态与预算。

模型按内容选择 Queue／Steer，程序保留用户优先、停止、`false` 和条数上限；没有复杂的任务语义调度器。成员查询历史是按需参考，不作为新用户指令；不展开工具、转发材料、图片或草稿。已有第 1 版动态工具会话通过临时 MCP 获得新版接口，不丢原会话。分享源码请使用 GitHub 克隆／源码 ZIP 或 README 的 `git archive` 命令，勿直接压缩带有 `.codex-room` 的运行目录。

```text
@开发 整理当前实现与我的目标，创建一个叫 reviewer 的原生子代理，请他先提意见。
我会过去跟他讨论，先别实施，也不要关闭他。
@reviewer 从你的角度看，这个方案有什么值得调整的地方？
```

子代理加入只作轻量提醒，不自动切走当前视图。用户可以通过 `@` 补全或成员列表进入，连续讨论后，选择有价值的内容，Ctrl+F 转给原来的开发成员。

`/stop reviewer` 停止原生子代理，并撤销尚未发出的用户转交。已在父会话中处理的转交无法从模型上下文里撤回；停止标记会拦截旧转交造成的后续唤醒，直到用户再次主动给该子代理发消息。

`/del reviewer` 先确认停止，再归档并移出 Room，不删除项目文件和 Codex 历史。删除父成员会连同其 Room 子代理一起处理；停止失败则保留成员供检查。已移除 child 不会被启动发现机制再次加回来。

## 原生协议边界

以实际验证的 `codex-cli 0.163.0` 为基准，并查阅 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

- 子代理保持原 thread，不新建独立 root 冒充续聊。仅发现当前房间所属的子树。
- MultiAgent V2 的 `canAcceptDirectInput=false` 子代理不接受普通 `turn/start`／`turn/steer`。Room 将用户消息交给已有 root，由其使用原生 `followup_task` 转给指定 child；因此会多一次父代理推理并占用父会话上下文。
- 同一 root 的用户转交串行确认；父代理忙时使用 steer。确认关联本次父 turn、目标 child 和转交后出现的原生交互活动。原生协议不公开完整的逐消息收据，不能据此宣称严格的逐字或 exactly-once 保证。无法确认会明确提示，不自动重发，并展示父代理回复供检查。
- 内部转交指令和成功转交的中间答复不混入可见聊天与转发选区。子代理原话照常展示；失败保留父代理的解释。
- 附加 child 不覆盖它的 cwd、模型或推理强度；界面显示实际返回的元数据。子代理设置由原生父子机制管理，Room 不保存一个未生效的独立模型／权限修改。
- 完整历史使用 turns/items 分页；流式内容与历史按 thread、turn、item 合流，不将已完成轮次降回运行中。缺失的旧 child 单独报错，不使其他成员离线。
- 仅对确实需要恢复子代理的 root 提前加载，普通空闲成员仍按需加载。旧 Textual 可阅读主要历史，原生子代理管理与续聊使用默认 Rust 界面。

## 验证

当前检查通过：166 项 Python 测试、20 项 Rust 测试、10 个真实 PTY 场景，以及真实 Codex 第 1 版会话升级、第 2 版动态工具、双入口成员查询、忙时显式 Steer、公开双向通信、重启恢复和轮流数到 11。40 项公开消息测试覆盖默认 Queue／显式 Steer、用户优先、提前回信与确认竞争、收据去重、来源校验、`false` 边界、停止、消息上限、输入来源隔离与投递不确定；6 项成员查询测试覆盖近期对话关联、截断、附件／草稿排除、分页和旧接口兼容。

复制修复补充 macOS ⌘C、Ctrl+Shift+C 和底部「复制」；20 项 Rust 测试、9 个 PTY 场景通过。终端按键协议测试验证先后选中不同文字确实覆盖旧复制内容、无选区 ⌘C 不退出，以及退出前恢复键盘模式。测试使用模拟剪贴板助手，不覆盖用户剪贴板。

后续增补：通信卡片及历史补载、双向可见和转发；成员栏切换／重选后在新视图完成重排时定位到底部，控件的鼠标释放不会落进正文触发工具操作。互发通信和子代理公开回复是不同数据源，当前 V2 不提供的通信正文不会被补写成所谓原文。真实模型已验证子代理向父代理 `send_message` 的反向通信记录。

- Python 全套回归；原生协议测试覆盖创建、多轮上下文、两级分页、提前审批、重复和过期事件、历史与流式合流、父代理忙时确认竞争、状态不明不重发、停止、递归删除及失败保留、旧 child 恢复失败和其他 root 隔离。
- Rust 单元测试与真实 PTY 场景，包含子代理显示、多轮输入、隐藏内部转交、重启恢复，以及原有输入／转发／长历史／拖选场景。

## 尚未纳入当前范围

这些是保留的边界，不作为本版已实现能力：

- 自动全员旁听、主动插话、无限讨论；不默认唤醒其他成员。
- `/add B --parent A` 快捷语法；目前通过自然语言让 A 创建原生 B。
- 任意 MCP elicitation 表单和 URL 验证界面，目前明确取消请求；已有审批和 Codex 补充问题可交互。
- 纯 Rust 通信层重写、预编译跨平台发行包和 Windows 实机体验验证。终端指针形状仍由宿主决定。
