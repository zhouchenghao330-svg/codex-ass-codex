# Codex Room

一个终端，多个独立的真实 Codex 会话。通过本机 `codex app-server` 接入，沿用现有 Codex 登录、模型服务和项目配置。

默认权限为 **Full Access**：`danger-full-access` + `approval_policy = "never"`。每位成员可独立设置模型、推理强度和权限，修改从下一轮开始生效。

## 启动

需要 [uv](https://docs.astral.sh/uv/) 和已登录、可正常运行的 Codex CLI（本机验证版本：0.163.0）。首次运行会安装 Python 依赖。

```sh
uv run codex-room
```

也支持 `uv run codex_room` 和 `uv run python -m codex_room`。用 `--cwd /path/to/project` 指定 Codex 的工作目录。

Windows 用户拿到 ZIP 后先完整解压，可双击 `start.bat`，也可在解压目录的 PowerShell 中运行同一命令。需要本机已安装 uv 和已登录的 Codex CLI；具体步骤见 [Windows ZIP 使用说明](WINDOWS.md)。文件锁支持 Windows/macOS/Linux，Windows 使用 Textual 的原生驱动，并处理 Codex 的标准 npm `.cmd` 启动器。

默认真实调用模型并允许执行任务。纯界面演示使用 `uv run codex-room --demo`，演示模式不连接 Codex。

默认只有消息、三行输入区和一行状态，成员侧栏默认收起。支持鼠标滚动消息和中文输入。

输入区会在发送前自动折行，按内容向上增高，最多显示 8 行（小终端会进一步限高），超出后在输入区内部滚动。长中文和无空格路径也会折行；粘贴保留原始换行。`Enter` 发送，`Shift+Enter` 或 `Ctrl+J` 手动换行，发送后恢复紧凑高度。

一次粘贴达到 1000 字符或 8 行时，输入框显示 `[Pasted Content 6361 chars]`，完整原文随消息发送。粘贴的本地图片路径显示为 `[Image #1]`，通过 Codex 的 `localImage` 输入发送；支持多张图片、带空格或引号的路径、`file://` 路径。普通文本里的路径保持文字，不会自动变成附件。

这些块可用左右方向键整块跨过，在块后按一次退格或在块前按 Delete 即可整块删除，`Ctrl+Z` / `Ctrl+Y` 撤销 / 重做；选中复制长粘贴块会复制其完整原文。光标放在长粘贴块前后按 `Alt+Enter` 可展开成可编辑文本。`↑` 调出的历史输入仍保留块和完整内容，重启后同样有效；终端需将图片粘贴或拖入转换成本地文件路径，图片文件需在发送时仍然存在。

点击聊天区或重新激活窗口即可直接输入；在消息区开始打字或粘贴也会自动回到输入框。选中文本和弹窗中的输入保持正常。

用鼠标拖动可高亮选择消息文字，包括 Markdown 正文、代码块和展开后的工具输出，也支持跨消息选择。`Ctrl+C` 复制选中文字，`Esc` 取消选中并回到输入框；没有选中文字时 `Ctrl+C` 仍退出，`Ctrl+Q` 始终退出。复制的是当前显示的文本，折叠的工具详情不会混入。macOS 同时写入本机剪贴板。滚轮每个事件滚动 1 行，方便定位内容。

拖到聊天区上下边缘会自动滚动并持续扩展选区，已经滚出屏幕的起点保持不变。选择范围仅包含聊天记录；鼠标越过成员栏、输入框或状态栏时不会把这些界面文字选进去。拖选期间和保留选区时，新回复不会把页面拉回底部。

拖动按字符边界选择，不额外包含终点字符；中文同一个字的两格映射到同一个字符。双击按 Orca 终端的默认分隔符选择连续文字片段（例如“取消；没有选区时”），三击选择当前行。点高亮区域内保留选区，点高亮外任意位置立即取消选区；不会因双击或三击而全选整条回复或整个聊天区。

Codex 回复支持 Markdown：标题、加粗、列表、引用、链接、表格、行内代码和带语法高亮的代码块。流式回复和恢复的历史消息使用相同的渲染方式；工具日志保留原始文本。

运行中的回复下方显示带旋转动效的 `Working`、当前阶段和耗时。收到 Codex 的公开思考摘要时显示摘要标题；没有摘要时显示实际运行阶段。完成、失败或停止后动效自动消失。

每条回复顶部显示成员名字、`@名字` 和工作目录。长路径自动缩略，悬停可查看完整路径。回复最底部显示 `Worked for 11m 32s · 20:25`：耗时从该轮实际开始计算，包含会话启动和工具执行，不包含排队等待；时间为本地结束时间。停止和失败也会保留对应耗时和结束时间，重启后可以继续查看。旧记录没有计时数据时不会补造耗时。

点击回复标题前的 `▾` 收起整条回复，`▸` 或收起后的单行摘要可重新展开。收起时保留名字、工作目录、摘要，以及运行状态或结束耗时，正文和工具详情隐藏；运行中的回复不会因新输出而自动展开。各条回复独立控制，切换全部 / 单人视图或重启后保持收起状态。收起的正文不会混入拖选复制，`Ctrl+T` 仍只控制工具详情。

新房间初始没有成员。`/add 名字` 创建普通 Codex 会话，名字只用于显示和 `@` 点名，应用不附加身份或职责提示词。

名字支持中文，例如 `/add 开发笔记`。用 `/rename a 环境排查` 给已有成员改名，或用 `/rename 新名` 改当前成员的名字；会话、工作目录、历史和正在运行的任务都保留。新名字会出现在 `@`、`/focus`、`/stop`、`/del` 的补全列表里，侧栏可一直收起。

## 转发对话与多人点名

在聊天区连续拖选一段对话（可跨多轮），松开后点击底部「转发」，或按 `Ctrl+F`。在临时列表中搜索并选择已有成员，也可直接「＋新建 Codex」。随后进入接收者的单人对话，输入框上方保留一块只读引用；补一句新任务、路径等说明，再按 Enter 一起发送。发送后留在该成员处，可以继续补充。

引用可点击预览、整块移除。默认只取选区中你与起始成员的对话；选区交错包含其他成员时，可切换为「整个选区」。选区边界处只带选中的正文，跨过的折叠回复、工具摘要会带完整内部内容，包括命令输出、工具参数、结果及文件 diff；长粘贴保留原文，图片作为图片输入发送。引用保留原发言者、来源工作目录与消息 ID，不自动摘要，也不追加选区外的历史。捕获后是一份快照，来源继续输出或改名不会修改草稿中的引用。

点击「← 返回来源」恢复原来的单人／全部视图和未发送草稿，并滚到该视图的最新消息。尚未发送的转发草稿会留在接收者处，回到该成员的单人对话可继续编辑。后台成员完成时轻量提示；需要补充信息或审批时，后台成员只提示，切到它后点击底部「回复请求」处理。

例如：与 A 排查出 dedup 未接入后，拖选这几轮讨论 → 转发给「开发笔记」→ 输入「写进 /path/to/Obsidian 的开发经验，说明上下文去重为什么重要」→ 发送 → 返回 A 继续原任务。普通 `Ctrl+C` 仍复制可见文字。

消息开头可连续点名：`@a @b 分别评价这个方案`。每位成员收到同一份任务，各自使用独立会话并行处理，彼此的回复不会自动投递。全部视图中用户任务合并显示，单人视图中各自保留该任务；每位成员的接收状态单独保存。重复点名只投递一次，不存在的名字会保留草稿并提示，不会先向部分成员发送。正文中普通提及的 `@名字` 保持文字；设置命令一次只作用于一个成员。

用 `/add 名字 路径` 为成员单独指定工作目录，例如 `/add a ~/code/project-a`。支持绝对路径、相对路径和 `~`；相对路径以群聊的工作目录为基准，带空格的路径请加引号。目录必须已存在，省略时沿用群聊目录。目录会传入 Codex 会话及每轮请求，并随成员保存；不同成员可以在不同项目中并行工作。

所有回复使用统一深色背景、米白色正文，用各自的彩色名字和左侧细竖线区分 Codex；工作目录、工具摘要和耗时使用中性灰，代码语法和 diff 保留原有含义颜色。`/add` 或 `Ctrl+N` 可在创建窗口中填写工作目录、选择身份颜色并预览；命令可写 `/add a ~/code/project-a --color blue`。仍兼容 `/add a blue` 和 `/add a #83c8e8`；如果相对目录与颜色同名，使用 `./blue` 指定目录。省略颜色时自动分配未占用的颜色，预设颜色用完后继续生成新颜色。手动选择已占用的颜色会提示更换，配色会随成员一起保存。

## 试试这些操作

```text
/add a
/add b
/add c blue
/add dev ~/code/project --color mint
/add paper "/Users/me/My Paper"
@a 你好
@b 查看当前目录
/focus b
/members
/model
@b /model
@b /model gpt-6.1-sol low
/permissions
@b /permissions workspace
/stop a
/del a
/reconnect
/help
```

- 点击左下角常驻的「› 成员／‹ 收起」展开 / 收起侧栏，也可用 `Ctrl+B`；点击成员切到与该成员的单人对话，同时切换默认接收者。
- 点击侧栏顶部「全部消息」恢复所有成员的对话；当前视图会高亮显示。默认接收者保持不变，仍可从输入框底部查看。
- 从 `@` 列表选中成员，或成功发送 `@名字 消息` 后，该成员会成为默认接收者；下一条直接输入继续发给它。
- `Ctrl+1/2/3` 或 `/focus 名字` 切到对应成员的单人对话；`/focus all` 回到聊天室的全部消息视图，默认接收者保持不变；`Ctrl+N` 添加成员。
- `/add 名字 [目录] [--color 颜色]` 指定工作目录和配色；颜色支持 blue、purple、mint、rose、中文颜色名及十六进制色值。
- `Ctrl+L` 切换全部消息 / 当前成员视图。
- 命令和参数支持自动弹出补全：`/mem` → `Tab` → `/members`；`/focus `、`/stop `、`/del ` 后选择成员；`/model ` 选择实际返回的模型及其支持的推理强度；`/permissions ` 选择权限。
- `/add 名字 ` 后可补全目录，支持相对路径、`~`、引号和带空格的目录名；`--color`、`--color=` 及旧式颜色参数也支持补全，已占用的配色不会列出。目录选中后，再按 Tab 继续补全子目录。
- 补全列表支持 `↑/↓`、`Tab`、`Enter` 和鼠标选择，`Esc` 关闭；选中只填入文本，不执行命令。补全后按 Enter 执行，完整命令直接按 Enter 也可执行。支持在光标处替换当前参数，保留后面的内容；普通聊天文本按 Tab 保持输入焦点。
- 输入 `@` 弹出成员列表，继续输入名字过滤；`↑/↓` 选择，`Tab` 或 `Enter` 确认，也可以鼠标点击。`Esc` 关闭。
- 只有完整匹配房间命令名时才执行本地命令；`/Users/...`、`/tmp` 等路径和其他未注册的斜杠文本按普通消息发送，`@名字 /Users/...` 同样支持。
- 确认成员会填入 `@名字 ` 并切换默认接收者，写好消息后再按 `Enter` 发送。
- 输入框为空时按 `↑` 调出上一条已提交的输入，继续用 `↑/↓` 翻阅；向下回到最新位置恢复草稿。调出的文字可编辑、发送，翻阅时保留临时修改和光标位置；原本有未发送文字时不会开始翻历史。补全列表打开时，`↑/↓` 优先选择候选。输入历史包含消息和命令，保留原有 `@名字`，连续重复提交只记一次，随房间保存；未成功提交的输入不会写入历史。
- `/model` 打开当前成员的模型和推理强度选择，也可用 `@名字 /model` 指定成员。
- `/permissions` 打开权限选择；可直接指定 `full`、`workspace`、`read-only`，兼容 `/permission`。
- 同一成员忙时，按 Enter 通过 `turn/steer` 将新消息追加到正在进行的这一轮，显示「已追加」，无需等待整轮回复完成；空闲时开始新一轮。会话正在启动时先短暂暂存，拿到当前 turn ID 后立即追加；若上一轮恰好结束，消息改由新一轮处理。传输错误或超时不会盲目重发，避免重复执行。不同成员仍可以同时工作。
- 追加消息按到达时间插在对话中：旧输出保持原位，新输出接在追加消息后，同一轮只有结尾显示总耗时。已开始的工具仍在原处更新结果。
- 工具调用默认折叠成一行，分别统计命令、其他工具和变更文件。总标题只切换「展开摘要／收起」，点击一次即可收起；「全部详情」单独展开完整内容，「仅看摘要」回到预览。各项摘要列出命令、MCP 服务/工具名、Codex 工具名以及输入和输出预览，单击某项可独立展开或收起。命令使用 shell 高亮，长命令自动换行。`Ctrl+T` 仍可统一展开 / 收起，正文保持可见。
- 文件变更按 Codex 返回的记录显示新增、修改、删除、重命名及各文件的 `+新增行数 -删除行数`，展开可查看完整 diff，新增绿色、删除红色。长路径在摘要中缩略，详情保留完整路径。计数反映工具此次记录的变更，不是仓库最终净差异；旧记录或工具未提供 diff 时保留原始输出，不补造变更。
- `/stop 名字` 停止该成员当前回复，并取消尚未发出的消息；已追加的指令随当前轮一起停止。
- `/del 名字` 移除成员和它在房间中的消息，先停止当前工作、取消尚未发出的消息，并将配置和会话记录归档至 `.codex-room/archives/`。也可用 `@名字 /del`；单独 `/del` 不会删除默认成员。同名重建从新会话开始，颜色可以重新分配。成员的工作目录、项目文件和 Codex 原生历史保留，其他成员继续工作。
- `F1` 查看帮助，`Ctrl+Q` 或 `Ctrl+C` 退出。

每个成员使用独立的 Codex thread。模型上下文由 Codex 自己维护；后续消息只发送新增内容，界面的全部消息不会广播给其他成员。

群聊显示记录、成员配置和 thread ID 保存在工作目录的 `.codex-room/state.json`，已加入 Git 忽略。重启后恢复会话，尚未完成或排队的请求不会自动重发。同一工作目录只允许打开一个真实群聊，避免并发覆盖状态。群聊内调整保存在成员配置中，日常 Codex 全局配置保持原值。

当前成员的普通审批和 Codex 补充问题会在 TUI 中弹出，后台成员使用轻量提醒。MCP 的任意表单交互暂未实现，遇到时会明确取消并提示。`/reconnect` 可重连失败或退出的 app-server。

## 预览与验证

技术选型实验尚未替换正式入口。运行 `uv run python scripts/terminal_lab.py --lines 10000`，可在同一个终端中从菜单选择 Rust Inline、Rust Fullscreen、当前 Textual、关闭鼠标捕获的 Textual；四组使用相同的模拟数据，不调用模型、不读写房间状态。操作与已知限制见 [实验说明](experiments/terminal-lab/README.md)。此前的 Python Inline 小样仍可用 `uv run scripts/native_terminal_probe.py` 启动。调研与功能迁移边界见 [终端呈现](docs/native-terminal-presentation.md)，未完成的子代理工作见 [功能交接](docs/next-version-handoff.md)。

```sh
uv run python scripts/preview.py
uv run python scripts/preview_tools.py
uv run python scripts/preview_composer.py
uv run python -m unittest discover -s tests -v
```

界面检查只用模拟回复，协议与交互测试使用本地测试服务。生成的截图在 `artifacts/` 中。

终端测试会在独立 PTY 中检查 Ctrl+Q、Ctrl+C、`/quit` 和异常退出后的键盘模式及退格恢复。界面只启用基本扩展键盘支持，退出时恢复调用方的键盘模式。

如果旧版本退出后退格变成了 `7u` / `127u`，可在受影响的终端运行以下命令，清除遗留的扩展键盘模式：

```sh
printf '\033[=0u'
```

真实端到端验证（会调用模型，包含只读 `pwd` 和可中断的 `sleep 30`，群聊状态放在临时目录）：

```sh
uv run python scripts/check_live.py
```

单独验证真实 `turn/steer`（调用模型，在临时目录执行一次 `sleep 3`，检查同一轮是否采纳追加指令）：

```sh
uv run python scripts/check_steer.py
```
