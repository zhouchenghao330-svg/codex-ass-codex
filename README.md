# Codex Room

一个终端，多个独立的 Codex 会话。正式界面使用 **Rust + Ratatui Fullscreen**：统一深色背景和米白正文，通过彩色名字与细竖线区分成员。Codex 连接和兼容存储继续由本地 Python 服务负责，沿用本机的 Codex 登录与项目配置。

## 启动

需要 [uv](https://docs.astral.sh/uv/) 和已登录、可正常运行的 Codex CLI。**普通使用无需安装 Rust**。从 GitHub 克隆后，在项目目录运行：

```sh
uv run codex_room
```

首次安装 Python 依赖并匿名下载项目指定版本的预编译界面，校验 SHA-256 后缓存；后续直接复用缓存，无需 GitHub Token。支持 macOS Apple Silicon / Intel、Windows x64 / ARM64、Linux x64 / ARM64。更新时先退出 Room，再 `git pull --ff-only` 并用原命令重开；项目更改界面版本时会自动下载对应的新程序，原房间保留。

同样支持 `uv run codex-room`、`uv run python -m codex_room`。通过 `--cwd /path/to/project` 指定房间目录。纯界面演示用 `--demo`，不连接 Codex、不写真实房间数据。

旧 Textual 界面保留为显式回退，不下载 Rust 界面：

```sh
uv run codex_room --legacy-ui
```

Windows 可双击 `start.bat`，步骤见 [Windows 说明](WINDOWS.md)。开发者修改 Rust 源码后使用 `uv run codex_room --build-ui`（需要 Rust 1.88+）；普通启动不会编译本地源码。缓存、网络故障及发布步骤见 [界面发行说明](docs/ui-distribution.md)。

本地修改尚未发布时，调试请统一使用 `--build-ui`；普通启动使用固定 Release 缓存，即使版本号相同，也不包含本地尚未发布的 Rust 界面修改。

## 成员与对话

新房间没有预设成员。名字只用于显示和点名，不会注入角色提示词。

```text
/add 开发 ~/code/project
/add 笔记 "/path/to/My Notes" --color mint
@开发 看看这个项目
@开发 @笔记 分别评价这个方案
/rename 开发 环境排查
/focus 笔记
/focus all
/adhd
/model
/fast
@环境排查 /fast off
@环境排查 /model 模型名 low
/permissions workspace
/stop 环境排查
/del 环境排查
/reconnect
/help
```

`/resume 会话ID [成员名]` 把本机已有的独立 Codex 会话接入 Room。可在 Orca 中点击「复制会话 ID」，例如：

```text
/resume 019f0000-1111-7222-8333-444444444444 项目开发
```

省略成员名会自动命名，之后可 `/rename`。不用先 `cd`，自动读取原会话的目录、模型、思考强度和权限；恢复用户提问、正文、工具详情及本地图片引用，继续使用同一个 thread ID。恢复本身不发起模型运行；再次恢复同一 ID 直接切到已有成员。也兼容在 `/resume` 后粘贴 Orca 的完整恢复命令，仅解析 ID，不执行 shell，也不会因为复制命令包含 Full Access 标志而扩大原会话权限。仅查找当前 Codex 数据目录中的会话，ID 本身不包含聊天记录。原生子代理请恢复父会话，子代理会随之加入。

接入前结束原窗口中的任务，接入后选择 Room 或原窗口其中一端继续；Room 不关闭或接管 Orca 窗口，也无法可靠判断另一个独立进程是否正在使用同一会话。已检测到运行中的会话会拒绝接入。恢复的对话保留原始会话标题；Room 自建成员的 Codex 标题为 `Room · 成员名`，并随 `/rename` 更新，避免 Orca 历史列表显示内部身份说明。使用默认 Rust 界面体验 `/resume`。

`/add 名字 [目录] [--color 颜色]` 支持中文名、绝对/相对路径、~ 和带引号的路径。省略目录沿用房间目录；省略颜色自动分配未占用的颜色。颜色支持预设名称和十六进制值。Ctrl+N 或「添加」预填创建命令，Tab 可补全目录、颜色等参数。

创建后自动弹出模型、思考强度的两步选择界面，可用方向键和 Enter 或鼠标点选。模型来自本机 Codex 返回的列表，强度只展示该模型支持的选项，默认选中从成员目录继承的配置；选择其他模型时选中该模型的默认强度。第二步确认后一起保存，任一步按 Esc 都保留原配置，成员仍已创建。`/model` 可随时重新打开选择界面，`/model 模型名 强度` 仍可直接设置。转发时新建成员也使用相同流程，引用会保留。

输入框上方的成员名、模型、思考强度和 Fast 状态均可点击。菜单在输入框上方展开：选择模型后在右侧选择强度，直接点强度则只打开强度菜单；窗口过窄时分步显示，按 ← 返回模型列表。确认强度后一起应用，Esc 或点击外部取消。点成员名可切换对话并保留各自草稿，点 Fast 可选择开关。设置从下一轮生效，不打断当前运行。

点击输入框上方的成员名、按 Ctrl+B 或输入 `/members`，在输入框上方打开同一个成员弹层。名字右侧显示实时「工作中／空闲／待回复」，下方显示目录和子代理归属；状态变化保留当前筛选及选择，不按忙闲重新排序。选中成员切换对话并保留各自草稿；「全部消息」、`/focus all` 或 Ctrl+L 可回到聊天室。弹层也可准备 `/add` 创建成员，Esc 或再次 Ctrl+B 收起。默认 Rust 界面不再显示底部「成员」按钮和占用正文宽度的侧栏，旧 Textual 界面沿用原有侧栏。

成员完成一轮任务或运行失败后，尚未查看的结果以小圆点和淡色底标记；输入框上方显示 `[N 待查看]`，点击打开成员弹层并定位第一个未读成员，忙闲变化不改变列表顺序。打开列表不会清除未读；结果展开后的末尾进入可见聊天区域时才清除，查看旧消息、折叠预览、菜单遮挡及终端失去焦点期间保留。终端焦点检测取决于宿主是否上报焦点事件。每位成员计一个标记，新任务开始后仍保留，按房间保存并跨重启恢复；导入历史不会将旧消息批量标为未读。

开头连续 @ 多位成员时，各自收到同一任务、使用独立 thread 并行处理；不存在的成员会在任何投递前报错。正文普通提及不会转发给别人。忙时用户新消息使用 `turn/steer` 追加到当前轮；启动期间先暂存，拿到 turn ID 后追加。不对超时或不确定的投递盲目重发。追加的用户消息位于对话中间，新输出接在它后面，旧工具结果保持原位。同伴消息默认排队，也可由发送者显式选择 Steer；用户消息优先。

默认权限为 **Full Access**（danger-full-access / never）。模型、强度和权限按成员保存，调整从下一轮生效。后台完成或请求交互只做轻量提示；可切到成员后点「回复请求」处理。MCP 任意表单暂不支持，会明确取消。`/del 名字` 先停止并归档该成员，不删除项目目录或 Codex 原生历史。

`@名字 /fast` 切换该成员的 Fast 模式，再执行一次关闭；直接 `/fast` 切换当前成员。也可明确 `/fast on`、`/fast off`。未设置时沿用该目录的 Codex 默认值，切换会提示实际开关状态并保存，从下一轮生效，不打断当前任务、不改全局配置或其他成员。关闭时显式选择 Standard，覆盖原来的 Fast 默认值；支持情况以本机 Codex 返回的模型目录为准，不支持时会明确提示。原生子代理的设置由父会话管理。此命令由 Python 服务处理，与 v0.2.3 预编译界面兼容。[Codex 官方 Fast 说明](https://learn.chatgpt.com/docs/agent-configuration/speed)。

## 阅读、输入与工具

- `/adhd` 切换窄栏居中阅读，也可用 `/adhd on`、`/adhd off`。聊天正文最多 92 列，窗口较窄时自动收缩；保留原有配色、输入框和成员切换入口。默认关闭，按房间保存，重启恢复；切换时尽量保持当前阅读位置，不向 Codex 发送消息。此功能使用默认 Rust 界面。
- 直接打字即可输入。Enter 发送，Ctrl+J 换行；Shift+Enter 取决于终端是否单独上报。输入自动折行，最多显示 8 行；↑/↓ 在空输入框中翻历史，在多行草稿中移动光标。
- `/mem` + Tab 补成 `/members`；@、命令、成员、模型、推理强度、权限、目录和颜色均支持补全。↑/↓、Tab/Enter 或鼠标选择候选，选中只填入文本，再按 Enter 执行。普通路径不会误认为命令。
- 一次粘贴达到 1000 字符或 8 行，显示 `[Pasted Content N chars]`；原文完整发送。本地图片路径显示 `[Image #1]`，以 localImage 发送。左右跨过整个块，Backspace/Delete 整块删除，Ctrl+Z/Y 撤销/重做，Alt+Enter 展开长文本；选中长粘贴块复制时还原完整原文。图片文件需仍然存在；终端需把图片粘贴/拖入转换为本地路径。
- 拖选只覆盖正文，可跨消息；双击片段、三击行，点高亮外或 Esc 取消。macOS 用 ⌘C 复制选区，也支持 Ctrl+C、Ctrl+Shift+C 和底部「复制」按钮；⌘C 无选区时提示，只有普通 Ctrl+C 无选区时退出，Ctrl+Q 始终退出。⌘C 需要终端上报 Command 修饰键（如 Orca 的增强键盘模式）；宿主拦截时可点「复制」。滚轮每次 1 行，PageUp/Down 翻页，Ctrl+End 或底部「底部」回到最新。
- 拖到正文上下边缘自动滚动。保留选区时正文排版暂时固定，后台继续工作；取消后合入新输出，避免锚点移动。调整终端宽度会清除旧选区并重排。
- 复制 Markdown 表格时按逻辑行输出，单元格之间用 Tab 分隔，去掉绘制边框和填充；排版换行不会拆开长链接。局部选区与转发只包含选中的文字；代码块内的字面表格保留原样。
- 完整的 `mermaid` 代码块自动显示为终端字符图，支持流程图、时序图、状态图、类图和 ER 图。流程图节点和连线标签里的 `<br>`、`<br/>`、`<br />` 按多行文字显示；横向流程图放不下时提示改为纵向布局，保留节点和关系。流式输出尚未闭合时显示源码；语法不支持、图太大或纵向也放不下时说明原因并保留源码，加宽窗口或关闭居中阅读后会重新排版。选区复制保留显示的字符图，整条消息转发和聊天存储保留原始 Mermaid。渲染器来自 OpenAI Codex，许可证可通过 `codexroom --licenses` 查看。
- Markdown、代码语法和 diff 使用各自的颜色。代码块隐藏 Markdown 围栏，保留代码正文、缩进和已有语法高亮；未识别语言按纯代码显示。点击回复标题折叠整条回复；工具标题切换摘要展开/收起，单项可独立查看详情，「全部详情」单独控制。命令、MCP/Codex 工具、文件新增/修改/删除/重命名分别显示，文件提供 +新增/-删除和完整 diff；计数是工具记录的变更，不是仓库最终净差异。
- 工作中显示动效、阶段与耗时，只展示公开思考摘要的标题。回复顶部是成员与目录，底部保留 `Worked for … · 结束时间`，失败或停止也保留计时。

## 转发

拖选连续对话 → Ctrl+F 或底部「转发」→ 搜索已有成员或新建 → 补一句任务后发送。引用可预览、移除，或从默认的「与来源成员的对话」切换到「整个选区」。

边界只带所选正文；跨过的折叠回复、工具摘要会带上内部详情，包括完整输出和文件 diff。长粘贴保留原文，图片随引用发送。快照保留原发言者、目录、消息 ID，不自动摘要，也不自动联系来源成员。接收者的现有草稿保留，可以继续聊几轮。

「返回来源」恢复原视图和原草稿，滚到最新消息；目标的未发送草稿留在那里。适合把排查讨论转给另一个 Codex 记笔记、调研，再回来继续讨论。

原生子代理也会加入成员列表：例如向 `@开发` 发送「创建一个叫 reviewer 的原生子代理，先讨论方案，不要关闭他」，随后可 `@reviewer` 连续讨论、查看其原话，再选区转发回开发成员。保留原 child thread，支持重启恢复、工具详情、审批、停止和归档移除。新版 V2 子代理的输入由父代理使用原生通信工具转交，会多一次父代理推理；未确认的转交会提示且不自动重发。子代理的模型和权限由父会话管理。完整边界见 [功能交接](docs/next-version-handoff.md)。

代理间通信另列为 `A → B` 卡片，在全部消息及双方的单独对话中可见，支持折叠和转发。协议提供 `prompt` 原文时按 Markdown 展示；本机 Codex 0.163 的 V2 `subAgentActivity` 只提供参与者和活动类型，没有通信正文，卡片会明确标注「Codex 未提供这条通信的正文」。这与子代理自己的公开回复不同；不会把公开回复、用户输入或推测内容冒充互发原文。既有工具记录可在启动时补载，按源 thread、turn、工具调用和接收者去重。

## 独立成员公开协作

现在可以让 `/add` 创建的独立成员直接互发公开消息，无需通过原生子代理。准备「开发」和「审查」两位成员后，直接说：

```text
@开发 把当前实现和我的目标整理一下，用 Room 的公开消息工具发给审查，
请他提意见。先讨论，别改代码，收到建议后再和我聊。
```

两边仍使用各自的上下文与工作目录。`A → B`、`B → A` 卡片展示完整的互发原文和投递状态，支持 Markdown、折叠、选字和转发；全部消息和双方单人视图都能看。后台通信不切换当前视图、不覆盖草稿。你可以随时 `@` 任意成员继续聊。

消息工具立即确认接收，不等对方回答；`delivery_mode` 默认为 `queue`，新求助／独立任务排队，相关结果、补充和紧急纠正可显式选 `steer` 追加到忙碌成员的当前轮。空闲时两种模式都启动新一轮。卡片显示所选模式与实际送达／追加状态，用户直接输入优先。`expect_reply` 每次必填：`true` 要求完成必要处理后回信，不是立即确认或超时期限；`false` 的自动回信由程序拦截，Steer 也不能绕过。后续输入会带上尚未回复的请求提醒，不自动催促或重试。每条协作链最多 12 条消息。`/stop` 停止该成员并撤销相关链尚未投递的消息；超时不盲目重发，重启不自动恢复未完成投递。

`room.list_members` 按需查询独立成员的稳定名字、显示名、目录、忙闲状态和待处理消息数；默认附最近 3 轮用户提问，可选最多 5 轮，每轮附对应 Codex 正文的简短预览（前 3 行、最多 600 字符）。较长用户文本保留前 2000 字符并标注截断；不展开工具输出、图片和转发材料，不读取草稿。可按名字查询或分页查看；返回的历史只作参考，不是新的用户指令。

成员只有稳定名字和可变显示名，不预设职责。每次输入更新当前身份、名单和忙闲状态。Room 允许 Full Access 成员主动寻求相关协助；同伴不能转授用户的修改权限，涉及修改时先向用户说明计划并等待批准。后者目前是模型行为约定，不是程序强制的只读沙箱；实际执行权限不变。

新会话使用动态 `room.send_message` 和 `room.list_members`；旧会话（包括只有旧版动态工具的成员）通过临时 MCP 适配器使用新版接口，保留原 thread 和上下文，不改全局 Codex 配置。此功能使用默认 Rust 界面，面向独立成员；原生子代理保留原有通信方式。详见 [公开通信说明](docs/public-messages.md)。

## 数据与维护

`.codex-room/state.json` 沿用 v2 格式，保留成员 thread、配置、历史、附件、计时，并保存各视图草稿。重启恢复原会话，未完成请求不自动重发。同一房间只允许一个真实实例。登录信息由 Codex 自己管理，不进入 Room 状态或仓库。

### 分享给同事

推荐让同事从 GitHub 克隆到新目录，使用自己的 Codex 登录与本地配置启动：

```sh
git clone https://github.com/zhouchenghao330-svg/codex-ass-codex.git
cd codex-ass-codex
uv run codex_room
```

Git 克隆不会带上被忽略的聊天状态、虚拟环境和编译缓存，Release 也只包含界面程序和校验文件。直接在 Finder 压缩整个项目目录会把 `.codex-room` 等本地文件一起带走；`.gitignore` 不过滤普通 ZIP。同事若已经解压过包含旧房间的包，仅 `git pull` 不会清除该目录；先退出 Room，重命名 `.codex-room` 留作备份，再启动会创建新房间。程序不会擅自删除已有房间。

界面与通信边界、缓存和当前限制见 [Rust 迁移说明](docs/rust-fullscreen.md)；旧界面操作见 [Textual 旧版说明](docs/textual-legacy.md)。

阅读辅助的独立对比 Demo：`uv run python scripts/reading_lab.py`，用 0–5 切换原样、行阅读尺、段落聚焦、段落加行提示、窄栏聚焦、仅窄栏居中；支持两种明暗风格、锁定、选字复制及模拟流式输出，不连接 Codex、不读写房间。操作与实验边界见 [阅读 Demo](docs/reading-demo.md)。正式 `/adhd` 采用方案 5，仅窄栏居中。

```sh
cargo test --locked --manifest-path terminal-ui/Cargo.toml
uv run python -m unittest discover -s tests -v
uv run scripts/check_rust_ui.py
```

PTY 检查只使用隔离的模拟服务，不读写用户房间或剪贴板。真实检查会调用模型两次：`uv run scripts/check_rust_ui_live.py`。

公开通信的真实检查：`uv run python scripts/check_peer_messages_live.py`，会在临时房间进行数次模型调用，验证旧会话兼容、双向原文和重启恢复。

四组对照实验保留：`uv run python scripts/terminal_lab.py --lines 10000`，见 [实验说明](experiments/terminal-lab/README.md)。

协议参考：[Codex app-server 官方文档](https://learn.chatgpt.com/docs/app-server)。
